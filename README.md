# HMAC Service
___

Мой проект. Локальная машина Mac Air M4 apple silicon.

## Зависимости

- `cpprestsdk` - простой интерфейс для создания веб-сервера
- `OpenSSL` - библиотека для использования алгоритмов криптографии (как правило, установлена по умолчанию)

Логи ошибок / валидных операций.
Дополнительный функционал: простая утилита для ротации секрета.
Электронная подпись — криптографический механизм подтверждения целостности и подлинности данных (а в асимметричных системах ещё и неотказуемости). В этом учебном проекте используется HMAC-SHA256 — симметричный MAC: отправитель и проверяющий используют один секретный ключ, подпись вычисляется по сообщению и секрету; получатель пересчитывает и сравнивает. 
Неотказуемость — свойство криптосистемы, при котором автор не может правдоподобно отрицать, что именно он создал и подписал сообщение.
Ограничения реализации в этом проекте: это не шифрование и не юридически значимая асимметричная ЭП (нет сертификатов, меток времени, цепочек доверия и неотказуемости); безопасность основывается на хранении общего секрета, его корректной ротации и ограничении доступа. Решение обеспечивает проверку «сообщение не изменили, и оно от того, кто знает ключ», но не скрывает содержимое и требует безопасного обмена ключом заранее.

API

1. Общие правила

Формат тела запроса: application/json, кодировка UTF-8.
Сообщение нормализуется как строка.
Подпись кодируется в base64url без паддинга (более подробное описание — ниже в алгоритме), чтобы избежать проблем с URL.
Ответы также в формате JSON.
2. Эндпоинты

POST /sign
Возвращает электронную подпись заданного сообщения.
Запрос:
{ 
  "msg": "string" 
} 
 Ответ (200):
{ 
  "signature": "base64url" 
} 
Ошибки:

500 — внутренняя ошибка.
Смотрите также раздел «Ошибки и коды». 
POST /verify
Проверяет, соответствует ли электронная подпись `signature` сообщению `msg`.
Запрос:
{ 
  "msg": "string", 
  "signature": "base64url" 
} 
 Ответ (200):
Подпись соответствует сообщению:
{ 
  "ok": true 
} 
Подпись не соответствует сообщению:
{ 
  "ok": false 
} 
 Ошибки: 
400 — отсутствует/невалиден msg или signature (не base64url).
500 — внутренняя ошибка.
Смотрите также раздел «Ошибки и коды».

Алгоритмы

HMAC_SHA256 — это способ проверить, что сообщение не изменили и что его сделал тот, у кого есть общий секрет (уникальная секретная строка-ключ). Берём текст сообщения и секретный ключ, пропускаем их через хеш-функцию SHA-256 по специальной схеме (HMAC), получаем короткую подпись (MAC). Получатель, зная тот же секрет, пересчитывает подпись и сравнивает: если полученная подпись совпала с подписью сообщения, значит, сообщение целое и от «своего» источника.
Важно понимать ограничения этого учебного примера: это не шифрование и не асимметричная ЭП — тут один общий секрет у обеих сторон.
1. Обработка запроса

Проверить наличие заголовка Content-Type: application/json. Если его нет, то ошибка 415.
Распарсить JSON → извлечь поле msg типа string. Если поля нет, то ошибка 400. Если длина поля больше max_msg_size_bytes, то ошибка 413.
Преобразовать строку msg в байты UTF-8.
Считать секрет из конфига и преобразовать его в массив байтовов для дальнейшей работы.
Подписать байты секретом через алгоритм HMAC-SHA256 (см. ниже).
Для эндпоинта /signature: 1. Вернуть полученную подпись в ответе в поле signature с кодом 200.
Для эндпоинта /verify: 1. Извлечь из входного JSON поле signature типа string. Если поля нет, то ошибка 400. Если длина поля больше max_msg_size_bytes, то ошибка 413. 2. Сравнить входной signature с рассчитанной подписью. 3. Если подписи совпадают, то вернуть ответ ok: true, иначе ok: false.
2. Подпись HMAC-SHA256

Получим подпись sig в виде массива байтов через алгоритм HMAC-SHA256 из входного массива байтов сообщения msg и ключа key:
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;

Mac mac = Mac.getInstance("HmacSHA256");
mac.init(new SecretKeySpec(key, "HmacSHA256"));
byte[] sig = mac.doFinal(msg); 
import hmac, hashlib
sig = hmac.new(key, msg, hashlib.sha256).digest() 
#include <openssl/hmac.h>
unsigned int len=0;
unsigned char out[EVP_MAX_MD_SIZE];
HMAC(EVP_sha256(), key, keylen, msg, msglen, out, &len); 
Преобразуем подпись sig (массив байтов) в строку base64 для получения строки, которую можно передавать в JSON:
import java.util.Base64;
String b64url = Base64.getUrlEncoder().withoutPadding().encodeToString(sig); 
import base64
b64url = base64.urlsafe_b64encode(sig).rstrip(b'=').decode('ascii') 
#include <openssl/evp.h>
#include <string>

std::string to_base64url(const unsigned char* sig, size_t len) {
    std::string out(4 * ((len + 2) / 3), '\0');
    int n = EVP_EncodeBlock(reinterpret_cast<unsigned char*>(&out[0]), sig, static_cast<int>(len));
    out.resize(n);
    for (char& c : out) { if (c == '+') c = '-'; else if (c == '/') c = '_'; }
    while (!out.empty() && out.back() == '=') out.pop_back();
    return out;
}

Ошибки и коды

400 Bad Request 
Пустой или нестроковый msg.
Невалидная signature (не base64url, неверная длина).
Превышен max_msg_size_bytes.
413 Payload Too Large — превышен лимит тела запроса.
415 Unsupported Media Type — не application/json.
500 Internal Server Error — непредвиденные ошибки (без утечки деталей).
Тело ответа с ошибкой должно содержать следующий JSON:
{ 
  "error": "invalid_signature_format" 
} 
Примеры кодов ошибок: invalid_json, invalid_msg, invalid_signature_format, config_error, internal.
Нефункциональные требования

1. Безопасность

Не логировать secret и полные входные данные; можно логировать длину.
Для сравнения двух подписей использовать тайминг-стойкое сравнение.
Ограничение размера тела запроса.
Права доступа на config.json.
Тайминг-стойкое сравнение (constant-time compare) — это сравнение двух байтовых массивов так, чтобы время выполнения не зависело от того, где находится первое несовпадение. Это нужно для защиты от атак по времени: если сравнивать обычным способом и выходить при первом различии, атакующий по задержкам сможет постепенно угадать подпись/HMAC.
Идея реализации: всегда проходить все байты, без ранних выходов и ветвлений по содержимому, накапливая XOR-различия.
if len(a) != len(b):           
    return false
diff = 0
for i in 0..len(a)-1:
    diff |= a[i] ^ b[i]
return diff == 0 
Важно:
не использовать обычное == для секретов;
не делать return false в цикле;
избегать оптимизаций, меняющих время.
В реальном коде предпочитайте готовые функции: Python hmac.compare_digest, Node.js crypto.timingSafeEqual, Java MessageDigest.isEqual, OpenSSL CRYPTO_memcmp.

Тесты (минимальный набор)

Подпись/проверка успеха msg="hello" → /sign → подпись → /verify → ok=true.
Неверная подпись Изменить 1 байт в signature → ok=false.
Изменённое сообщение Подпись для "hello", проверка "hello!" → ok=false.
Невалидная base64url Поле signature="@@@" → 400 invalid_signature_format.
Пустой msg Поле msg="" → 400 invalid_msg.
Большое сообщение Сообщение > max_msg_size_bytes → 413.
Стабильность кодирования Подписи детерминированы: одинаковый msg → одинаковая signature (при неизменном секрете).
Тайминг-стойкое сравнение Тест на покрытие: используется constant-time compare (проверяется через юнит и ревью кода).
Конфиг-ошибки Некорректный secret в config.json → сервер не стартует с понятной ошибкой.
